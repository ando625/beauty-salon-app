## アプリの概要

このアプリを一言で言うと、**「お客がWebから予約でき、スタッフが予約をカレンダーで管理できる、美容室向けオンライン予約システム」**です。

お客はログイン不要でスタッフ・日時・メニューを選んで予約でき、予約確定後は**自動でメール通知**が届きます。スタッフ側はパスワードでログインした管理画面からカレンダー形式で予約を確認・キャンセルできます。

Next.js（フロントエンド）× NestJS（バックエンド）の2層構成で構築し、**TypeScriptによる型安全な設計**と**JWT認証**の実務的な使い方を学ぶことを目的として開発しました。

## こだわったポイント

### 1. お客はログインなしで予約できる
お客側はアカウント登録やログインが一切不要です。名前・電話番号・メールアドレスを入力するだけで予約が完結します。「とにかく簡単に予約できる」という体験を一番大事にしました。

### 2. スタッフを指名するか、自動で割り当てるか選べる
お客はスタッフを指名することも「誰でもいい」を選ぶこともできます。「誰でもいい」を選んだ場合、その日・その時間に空いているスタッフの中から**その日の予約件数が一番少ないスタッフに自動で割り当てる**ようにしました。特定のスタッフだけに予約が集中しないよう、均等に振り分ける仕組みです。

### 3. 空いている時間枠だけを表示する
スタッフと日付を選ぶと、その組み合わせで空いている時間枠だけがサーバーから取得されて表示されます。すでに予約が入っている時間は最初から選択肢に出てこないため、同じ時間に2件予約が入る（ダブルブッキング）が起きない仕組みになっています。

### 4. 予約が確定したら自動でメールが届く
予約が完了した瞬間、**Resend**というメール送信サービスを使ってお客とサロンの両方に自動でメールを送ります。お客には「予約が取れましたよ」という確認メール、サロンには「新しい予約が入りましたよ」という通知メールが届きます。

### 5. パスワードがないと管理画面に入れない
管理画面はパスワードでログインしないと開けない仕組みにしました。ログインが成功すると**トークン**（「この人は正しくログインした」という証明書のようなもの）をブラウザに保存します。次回アクセス時はこのトークンを確認して「正規のスタッフかどうか」を判断します。パスワードの照合には悪意のある攻撃への対策も入れています。


### 6. 全部まとめてDockerで管理
フロントエンド・バックエンド・データベース・DB管理画面の4つのサービスを**Docker**（仮想の箱）にまとめて管理しています。コマンド1つで全部が起動でき、「自分のPCでは動くのに他の人のPCでは動かない」という問題が起きません。また、データベースが完全に起動し終わってからバックエンドが起動するよう、起動の順番も制御しています。

### 7. 機能ごとに部品を分けた設計
バックエンドは「予約」「スタッフ」「メニュー」「メール送信」の4つの部品に分けて作りました。1つの部品に1つの役割だけを持たせることで、「どこを直せばいいか」がすぐ分かり、1か所を修正しても他の部分に影響が出にくくなっています。

### 8. データの形を事前に決めて開発した
フロントエンドとバックエンド両方でTypeScriptを使っています。「この予約データには必ず日付・時間・スタッフ名が入る」というルールをコードで先に決めておくことで、間違ったデータを渡してしまうミスをコードを動かす前に発見できます。

### 9. データベースの設計図をファイルで管理
テーブルの構造（どんな列があるか、どのテーブルとつながっているか）を `schema.prisma` という1つのファイルで管理しています。設計を変えたいときはこのファイルを書き換えてコマンドを実行するだけで、データベースに自動で反映されます。

## 苦労した点・学んだこと

### 問題1：Dockerの中でサービス同士がつながらなかった

**例え：** 「隣の部屋に荷物を届けて」と頼んだら、自分の部屋に届けてしまった。

**何が起きたか：**
Dockerは各サービス（フロントエンド・バックエンドなど）をそれぞれ独立した「箱」の中で動かします。フロントエンドの箱の中から「localhost:3001（自分のPC上のバックエンド）」に接続しようとしたところ、「自分の箱の中の3001番」を探してしまい、バックエンドの箱には届きませんでした。

**どう直したか：**
Dockerでは「サービスの名前」をそのままアドレスとして使えます。`localhost` の代わりに `backend`（バックエンドのサービス名）を指定することで、正しく接続できるようになりました。

```
# 修正前（つながらない）
API_URL=http://localhost:3001

# 修正後（つながる）
API_URL=http://backend:3001
```


「Dockerでは各サービスが独立した環境で動くので、localhostは自分自身の箱の中を指してしまいます。サービス名をアドレスとして使うことで、正しい箱に届くようになりました」

---

### 問題2：カレンダーがエラーになってうまく表示できなかった

**例え：** お店が「ハンバーグを用意した」と伝えたのに、テーブルに届いたのはカレーだった。

**何が起きたか：**
Next.jsはページを表示するとき、まずサーバー側でHTMLを作ってからブラウザに送ります。カレンダーを表示する処理がサーバー側でも動いていましたが、「今日の日付」の計算がサーバーとブラウザで少しズレていたため、「サーバーが作ったHTML」と「ブラウザが作ったHTML」が一致せずエラーになりました。

**どう直したか：**
「ブラウザに画面が表示された後かどうか」を記録する目印（`isMounted`）を作りました。この目印が「表示済み」になってからだけカレンダーを描画するようにしたことで、サーバーとブラウザのズレがなくなりエラーが解消されました。

```typescript
// ブラウザに表示されたかどうかの目印
const [isMounted, setIsMounted] = useState(false);

// 画面が表示されたら目印をONにする
useEffect(() => {
  setIsMounted(true);
}, []);

// 目印がONになってからだけカレンダーを描画する
{isMounted && <カレンダー />}
```


「Next.jsはサーバーとブラウザの両方でコードを動かします。日付の計算は実行する環境によって結果が変わることがあるので、ブラウザに画面が表示されてからだけ実行するよう制御しました」

---

### 問題3：パスワードのデータがDockerに読み込まれると途中で消えた

**例え：** 大事な暗号文を封筒に入れて送ったら、配達中に封筒が勝手に開けられて中身が一部消えてしまった。

**何が起きたか：**
パスワードを安全な形式に変換した文字列（`$2b$12$xxxx...` という形）を環境変数に保存しようとしました。ところがこの文字列には `$` がたくさん含まれており、Dockerが `$` を「変数の始まり」と勘違いしてしまい、文字列が途中から切れてしまいました。

```
正しい値: $2b$12$p5z8M0lURBt1Lg/7MUzrte...
実際に入った値: $2b$12/7MUzrte...  ← 途中が消えた！
```

**どう直したか：**
`$` が多い保存形式をやめて、パスワードをそのまま環境変数に入れる方法に切り替えました。比較するときは「必ず同じ時間がかかる照合方法」を使うことで、セキュリティを保ちつつ `$` の問題も解決しました。

```typescript
// 必ず同じ時間がかかる比較方法（攻撃者に処理時間を読まれない）
const isValid = crypto.timingSafeEqual(
  Buffer.from(入力されたパスワード),
  Buffer.from(環境変数のパスワード)
);
```


「Dockerの設定ファイルは `$` を特別な記号として扱うため、パスワードの保存形式が壊れてしまいました。`$` を含まない別の方法に切り替えることで解決しました」

---

### 問題4：データを取得してもスタッフ名やメニュー名が入っていなかった

**例え：** 「予約の情報を見せて」と言ったら、「スタッフのID番号：2」とだけ書かれた紙を渡されて、名前が分からなかった。

**何が起きたか：**
予約データを取得したとき、返ってきたデータに「スタッフのID番号」は入っていましたが、スタッフの名前は入っていませんでした。使っているデータベースツール（Prisma）は、特に指定しないと「関係する別のテーブルのデータは取ってこない」という仕様だったためです。

**どう直したか：**
データを取得するときに「スタッフ情報・メニュー情報・お客様情報も一緒に取ってきて」という指示（`include`）を追加しました。Laravelで言うと`with()`と同じ感じ。

```typescript
// include を追加する前 → スタッフ名が入ってこない
prisma.reservation.findMany()

// include を追加した後 → スタッフ名もメニュー名も一緒に取れる
prisma.reservation.findMany({
  include: {
    staff: { include: { user: true } },        // スタッフ名も取る
    reservationMenus: { include: { menu: true } }, // メニュー名も取る
    guestInfo: true,                            // お客様情報も取る
  },
});
```

「Prismaは指定しないと関連するテーブルのデータを取ってきません。includeで必要な関連データも一緒に取得するよう指定することで解決しました。Laravelのwith()と同じ考え方です」

## 主な機能

| 機能名 | 内容 |
|--------|------|
| 予約フォーム | スタッフ指名・日時・メニューを選んで予約 |
| 空き枠自動計算 | スタッフ×日付の組み合わせで空き枠をリアルタイム取得 |

| キャンセル | モーダルからワンクリックでキャンセル（論理削除） |
| ログイン保護 | JWT認証で管理画面を保護。未ログインは自動リダイレクト |
| トップページ | サロン紹介・メニュー一覧・予約ボタン |

## セットアップ方法

### 前提条件
- Docker / Docker Compose がインストール済みであること

---

### 手順1 : リポジトリをクローン

```bash
git clone https://github.com/ando625/beauty-salon-app.git
cd beauty-salon-app
```

---

### 手順2 : 環境変数を設定

ルートの `.env` を作成：

```env
POSTGRES_DB=beauty_salon
POSTGRES_USER=postgres
POSTGRES_PASSWORD=password123
DATABASE_URL=postgresql://postgres:password123@database:5432/beauty_salon
PGADMIN_EMAIL=admin@admin.com
PGADMIN_PASSWORD=admin
RESEND_API_KEY=your_resend_api_key
SALON_EMAIL=your_salon_email@example.com
```

`frontend/.env` を作成：

```env
API_URL=http://backend:3001
NEXT_PUBLIC_API_URL=http://localhost:3001
JWT_SECRET=your_random_secret_key
ADMIN_PASSWORD=your_admin_password
```

---

### 手順3 : Dockerコンテナを起動

```bash
docker compose up -d --build
```

---

### 手順4 : DBマイグレーション・シードデータ投入

```bash
# マイグレーション実行
docker compose exec backend npx prisma migrate dev

# シードデータ投入（スタッフ2名・メニュー4件）
docker compose exec backend npm run seed
```

---

### 手順5 : アクセス確認

| サービス | URL |
|----------|-----|
| フロントエンド（Next.js） | http://localhost:3000 |
| バックエンドAPI（NestJS） | http://localhost:3001 |
| DB管理画面（pgAdmin） | http://localhost:8080 |
